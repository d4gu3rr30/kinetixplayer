# Kinetix для iPhone

Нативная оболочка на Swift: WKWebView показывает тот же интерфейс, что и в приложении для Android, а локальный HTTP-сервер внутри процесса отдаёт веб-сборку и мосты к YouTube и Deezer. Данные (аккаунт, плейлисты, история, моменты) хранятся в localStorage WebView — компьютер и сервер не нужны.

Собрать `.ipa` можно только на macOS: Windows не умеет подписывать iOS-приложения. На Windows команда `npm run ios:build` собирает веб-часть и обновляет `ios/Kinetix/www`.

## Что внутри

- `Kinetix/AppDelegate.swift` — запуск, фоновое аудио (`AVAudioSession.playback`).
- `Kinetix/WebViewController.swift` — WKWebView, мост `window.kinetixAndroid.saveFile` (лист «Поделиться»), свайп от левого края как «назад», внешние ссылки в Safari.
- `Kinetix/KinetixServer.swift` — локальный сервер `127.0.0.1:47821–47832`, статика, стриминг аудио с поддержкой Range, фото исполнителей.
- `Kinetix/InnerTube.swift` — поиск и потоки YouTube через клиент ANDROID_VR, прокси Deezer.
- `Kinetix/www` — собранный веб-интерфейс (обновляется скриптом сборки).
- `Kinetix.xcodeproj` — проект и общая схема `Kinetix`.

Порт фиксирован намеренно: localStorage привязан к источнику (хост + порт), и при случайном порте аккаунт «пропадал» бы при каждом запуске.

## Требования

- macOS 13 или новее, Xcode 15+.
- iPhone с iOS 15+.
- Apple ID (бесплатный аккаунт подходит для установки на свой телефон на 7 дней, платный — на год).

## Запуск на iPhone

1. Перенесите папку `ios` на Mac (или склонируйте проект целиком).
2. Откройте `ios/Kinetix.xcodeproj` в Xcode.
3. Выберите цель **Kinetix** → вкладка **Signing & Capabilities** → **Team** = ваша команда.
4. Если `app.kinetix.player` занят, поменяйте **Bundle Identifier** на свой, например `ru.вашеимя.kinetix`.
5. Подключите iPhone, выберите его в верхней панели и нажмите **Run** (⌘R).
6. На телефоне: **Настройки → Основные → VPN и управление устройством** → доверьтесь своему профилю разработчика.

## Сборка

Сначала обновите веб-сборку и ассеты проекта:

```bash
npm run ios:build
```

На macOS та же команда дополнительно собирает приложение для симулятора (без подписи) и печатает путь к `Kinetix.app`.

Собрать `.ipa`:

```bash
APPLE_TEAM_ID=XXXXXXXXXX npm run ios:build -- --archive
```

- `APPLE_TEAM_ID` — идентификатор команды из [developer.apple.com](https://developer.apple.com/account) (10 символов).
- `IOS_BUNDLE_ID` — переопределить bundle id.
- `IOS_EXPORT_METHOD` — способ экспорта, по умолчанию `development`; для тестовых устройств также подходит `ad-hoc`.

Готовый файл появится в `release/ios/Kinetix.ipa`. Установить его можно через Apple Configurator, Xcode → **Window → Devices and Simulators** или Transporter/TestFlight.

## Как это работает

- При запуске приложение поднимает сервер на первом свободном порту из диапазона 47821–47832 и открывает `http://127.0.0.1:<порт>/?android=1&ios=1`.
- Флаг `android=1` включает клиентский слой данных (аккаунт в localStorage), `ios=1` добавляет отступы под вырез и домашний индикатор.
- Поиск и воспроизведение YouTube идут напрямую с устройства; аудио проксируется локальным сервером, поэтому работают перемотка и фоновое воспроизведение.
- Сохранение карточки Момента или файла переноса открывает системный лист «Поделиться», откуда файл можно положить в «Файлы».
- Свайп от левого края экрана работает как системная кнопка «назад» внутри приложения.

## Если что-то не так

- **«Signing for Kinetix requires a development team»** — не выбрана команда на вкладке Signing & Capabilities.
- **«Untrusted Developer»** на iPhone — доверьтесь профилю в настройках устройства.
- **«Нет свободного локального порта»** — порты 47821–47832 заняты; перезапустите приложение.
- **YouTube не отдаёт трек** — проверьте интернет; отдельные видео требуют входа в аккаунт, включите другой трек.
- **Аккаунт не переносится с Android** — экспортируйте данные в настройках Android-версии и импортируйте файл в настройках iOS-версии.
